# Glossary and naming hazards

[Documentation index](../README.md) · [Conceptual guide](Concepts.md) · [Shells and compensation](Shells_and_Compensation.md)

Definitions below describe **this project's usage**. Source vocabulary, engineering rules and everyday words should not be assumed interchangeable. Formal definitions come from the [Companion Theory](../../project_sources/HLE_Final_Build_Companion_Theory_v1_0.txt) and [specification](../HLE_Full_Crux_Build_Specification_v12.md); implementation boundaries are in [Capabilities](Capabilities.md).

## Content, access and work

| Term | Meaning here |
| --- | --- |
| HLE | Holonic Living Engine, the historical project name retained in modules, schemas and filenames. The current project is Socionics Research Lab. |
| Holon / participant / actor | “Holon” belongs to the broader conception of a whole that can also be a part. An actor in the implementation is an explicitly represented participant with its own access and resources; not every object is an actor. |
| Object identity / revision | Identity persists through versioned change; a reference names both identity and exact revision. Equal descriptions do not merge two instances. |
| Particular | A precise accessed detail tied to an exact source. It is distinct from a participant's interpretation of that detail. |
| Fool's Memory | Contextual conceptual relations, tension and continuity supported by exact particulars; not an omniscient memory or a language model. |
| Binding | A retained actor-owned association or interpretation with scope and evidence. It does not make the associated proposition true. |
| Disclosure / delivery / reading | Permission to expose selected information, an addressed transfer, and paid processing by the recipient. Each is a separate event. |
| Evidence / receipt | Evidence is a supporting record or raw world. A receipt records particular access or paid work; possessing a label is insufficient. |
| Demand | Supplied, owned content describing a needed outcome and priorities. It is not a claim of spontaneous desire formation. |
| Opportunity | Declared conditions under which a demand can be attempted. Missing opportunity must not be confused with failure under a valid opportunity. |
| Recipe | A versioned executable transformation for particular input schemas and scope. An automatic selection request does not name it. |
| Native | Executed through the relevant engine's ordinary paid operations and validators, rather than a descriptive evaluator label. The term does not mean biologically innate or automatically acquired. |
| Context / scope | The declared setting and applicability boundary of a claim, relation or capacity. An exact-target correction and a reusable context-bound capacity have different scopes. |
| Provenance / lineage | References to the actual inputs, events, ownership and revisions through which something arose or changed. |
| Primitive / competence / acquired use | A supported operation; the ability to use it must satisfy the relevant practice/acquisition contract. A procedure definition or lesson alone grants no skill. |
| Wallet / paid work | Finite integer energy and time accounting. “Paid” denotes modeled expenditure, not money or a billing service. |
| Modeled cost / machine cost | Participant charges versus host CPU, memory, serialization and I/O. Speeding computation up cannot refund participant work. |
| Quantum | The bounded amount of work permitted in a scheduler turn. |
| Checkpoint / restore | A schema-specific saved state and exact continuation. Use the engine or scheduler class that produced it. |
| Material / source material | A physical resource in material operations; in Shell/development records, retained originating tension/history. A Shell's “material” is not necessarily a physical object. |

## Formal structures

| Term | Meaning here |
| --- | --- |
| Model A | The eight-position formal carrier and type frames used by the preserved kernel. |
| Position / element / type | A seat in the type's organization; one of Ne/Ni/Se/Si/Te/Ti/Fe/Fi; a frame assigning elements to positions. They are not interchangeable identifiers. |
| Dimensionality | Integer 1–4 derived from position fields, used by the preserved work-price rule. It is not a measured amount of intelligence or a geometric dimension of the entire world. |
| Crux | The fixed map of 16 ordered routes between I, IT, WE and ITS. |
| I / IT / WE / ITS | Personal, concrete, shared and systemic perspectives on content and consequences. They are not four separate universes. |
| Route / realization | Formal origin→destination relationship versus the actual paid transformation satisfying that relationship's obligations. |
| Conductivity | Whether the realized processing fulfills the declared content/destination obligations. It is an assessed outcome, not a property granted by a route name. |
| Polarity / face | Accumulation or expenditure. A “face” in test tooling means this polarity, not a separate route. |
| Accumulation / expenditure | Register/refine/prepare versus externalize/couple/hand onward. Both cost work; neither determines privacy or truth. |
| Cell | One route under one polarity: 16 × 2 = 32. Not a type or a test method. |
| Fold | The four single-function perspective edges. I–IT and WE–ITS need composed paths with actual intermediate handoffs. |
| Self-route | Same origin and destination. Content can change and work must still be paid. |
| Formal inverse | Reversed endpoints only; not an undo, refund or erasure of history. |
| Support seat | A5/A7 for accumulation, A6/A8 for expenditure under the current processing rule. |
| Model G | Read-only names, blocks, signs, grades and A↔G mapping over the carrier. It is not an active energy model in Release 1.0. |
| Grade | Model G integer 0–3; distinct from dimensionality. Current processing still uses the inherited dimensionality rule. |
| Creative / Demonstrative | Qualify the model: G2 Creative = A8 demonstrative; G5 Demonstrative = A2 creative. |
| Super-Ego map / axis | The value-bit flip and its pairs {A1,A3}, {A2,A4}, {A5,A7}, {A6,A8}. The algebraic name is not a psychological diagnosis. |
| DCNH | Dominant, Creative, Normalizing, Harmonizing; the module returns structural formula/axis correspondences. No actor subtype is assigned. |
| Load / tilt | Sum and difference over the two poles of an axis in a supplied integer field. Not a calibrated conditioning strength. |
| Club | NT, NF, ST or SF. The proposed club/perspective correspondence is tagged as a bridge/postulate. |

## Shells and change

| Term | Meaning here |
| --- | --- |
| Shell | A persistent deformation of encounter that changes actual processing or a later decision. See the [dedicated guide](Shells_and_Compensation.md). |
| Compensation | In the project's illustrated mechanism, an accommodating procedure can enable immediate action while leaving an unnecessary dependency intact. Broader psychological uses are not automatically equivalent. |
| Pattern | A versioned owner/context/cue/trigger-specific record of executable effects and originating evidence. |
| Cue / trigger | An address used for contextual recall; an explicit affordance/opportunity feature used for matching a pattern. Neither is an assessor diagnosis. |
| Owner / target / carrier / bearer | Participant maintaining the pattern; encountered object; means/person through which it is expressed; declared party affected. These roles can differ. A bearer field alone does not transfer resources or create an obligation. |
| Effect kind / diagnostic sign | Five executable effects versus four trace/control-based signs. They are distinct enumerations. |
| Generated / injected fixture | Formed through an implemented evidence rule versus supplied by the evaluator to exercise an operator. Only approval formation is generated in the current Shell language. |
| Prevention / active interruption | Stopping before initiation versus stopping after paid work has produced an intermediate. Neither completes the intended destination. |
| Local release | Paid correction of a supported attribution for a specific target revision. Here “release” is a development operation, not a software release. |
| Practice / reorganization / reownership | Retention of observed actual response; reusable guarded capacity from independent practice; later evidence-based treatment of originating material. None is blanket clearance. |
| Recurrence / clearance | Reactivation under renewed demand; an assessment requiring positive supported evidence. Silence, quiet or a successful unrelated task is insufficient. |
| Institution | A versioned public rule tied to exact group/consent history. Changing a personal belief does not amend it. |
| Development | Retained causal change usable later in the declared domain. Repetition or renamed outputs alone are insufficient. |

## Evaluation and history

| Term | Meaning here |
| --- | --- |
| Setting | Content domain: inherited canonical tools/resources or timed workflow runbooks. |
| Canonical | Usually the inherited first content setting in release comparisons. In serialization, “canonical” instead refers to a deterministic representation; read the surrounding API. |
| Witness / raw world | Saved concrete execution showing a claim through its objects, transactions and access history. |
| Control | Matched intervention, such as withholding a defining output or bypassing a gate; intentionally invalid controls should fail the relevant ordinary auditor. |
| Independent auditor | A reconstruction that does not call the selector/executor/scheduler it audits. Shared specification/record definitions remain common. This is not a claim of independent external authorship. |
| Source freeze / hash | Exact evaluated-file list and digests; it records the code that produced a counted run. Current documentation may be newer than a historical frozen delivery. |
| Prospective protocol / matched panel | A declared evaluation contract recorded before implementation or the counted run; a fixed set of comparison conditions with specified controls and denominators. |
| Job / method / worker | One required orchestration command; a distinct test method ID; a measurement subprocess. The 54/742/81 counts use different denominators. |
| Milestone C7 / register C7 | Seventh software milestone versus a numbered theoretical open item. Software completion does not close the theoretical register. |
| U / C / FB / Corrective | Unified-object layers; Full Crux milestones; final-build batches; preserved corrective batches. |
| R21B / pyref | Preserved rebuild kernel versus the separately sealed 5.2.1 reference kernel not supplied for this release. |
| `integrate` / Integrate | The inherited native request `integrate` realizes IT→I (Embody). The Crux route Integrate is ITS→ITS. Existing APIs keep their original meanings. |
| Phase 7 / R5 | Proposed energy/conditioning experiment and the separate author ruling required to start it. Neither is implied by permission to improve documentation. |
