# C4 — composition and nested meaning

Engineering contract v1. C4 extends the C3 engine in place. The route grammar, Fold families, Model A accounting, access ledger, material law and earlier contracts are retained. This is an explicit finite implementation of the specification's bounded nesting proposal, not a proof of general cross-level equivalence.

## Typed composition

`CruxCompositionEngine` subclasses `CrossingEngine`. `CruxCompositionRequest` adds eight recipes. It uses the existing paid progression and checkpoint replay. The `crux_composition_` prefix distinguishes this layer from the preserved U9 composition machinery.

| Operation | Inputs and work | Result |
| --- | --- | --- |
| Commune renewal offer | A generated shared prior and an owned present intention; paid F/F return | An addressed offer referring to that exact prior, with explicit proposed limit and assent |
| Commune, both faces | Shared prior, renewal offer, separately paid receiver reply; F/F return | Revised shared interpretation or commitment. Prior difference, present unequal positions, participants, assent and exact exchange survive |
| Integrate, both faces | At least two generated conditional models in the same scope; N/N return | Conjunction of their constraints, retaining individual limits, components, assumptions and uncertainty. Expenditure couples only arrangements already held under the actor's authority |
| Context transfer | An owned source model, owned local intention and an actual paid-read local observation; N/N return | A qualified model in the destination context. Its cap is limited by all three inputs; source context remains explicit and systemic authority is not copied |
| Parent review | One to eight exact terminal child operations, their accessible outputs and declared handoff links; N/N return | A nested evidence organization with child outcomes, per-child polarities, explicit completeness and distinct-operation spending |
| Release | A current parent organization and one of its exact actor-owned model children; N/N return | That model becomes usable only if the declared parent outcome is complete. Blocked parent evidence yields no numeric allowance |

The first semantic step creates scoped composition work. The second consumes that exact paid intermediate. No adapter changes physical state by itself. Apply, Mobilize and subsequent enactment still pay through the native material executor.

This language extends the C3 conditional allocation dialect. It does not cast numeric constraints into the preserved C2 maintenance-interface graph. Those are distinct schemas; endpoint equality alone cannot convert between them. Earlier C2/U9 procedures continue through their existing contracts.

## Five connected families

Every supplied circuit passes generated outputs forward, then reviews its principal child movements with explicit links:

1. Theorize → Apply → Embody uses the actual received consumption outcome in a retained policy. Returning to I does not restore stock or refund work.
2. Share → Commune → Identify preserves an earlier exchange, then changes the shared limit through an independently answered renewal and incorporates it into personal meaning.
3. Coordinate → Mobilize uses observed conditions and actual uptake to authorize bounded concrete participation.
4. Institutionalize → Educate teaches the exact ratified rule in the original group. The receiver answers through its own paid processing; understanding remains distinct from assent and practiced competence.
5. Organize → Integrate → Apply combines generated resource constraints and uses the resulting system in concrete consumption. Individual constraints and historical evidence remain addressable.

Requests, initial intentions, resources and exchange opportunities are fixture inputs. These circuits are not a participant selector. Some circuits contain mixed polarities and others legitimately use a single face throughout; every movement retains its actual face. The parent is an ITS → ITS evidence organization, not a compressed replacement for the child trajectory.

## Bounded parent contract

A child claim contains an exact terminal operation revision and an output belonging to it. Material children supply a paid-read actual observation; semantic children supply a current owned binding or addressed public message. The parent additionally pays to read each child's receipt fields: actor, context, terminal status, actual spending and event reference.

The present parent contract certifies one actor's child operations in a common context and target. Other participants contribute through the existing public exchanges, votes and assent dependencies. The parent cannot certify another actor's private job or grant its competence. General aggregation across independently owned child holons remains open.

An explicit link requires compatible formal endpoints **and** the exact upstream output among the downstream operation's source references. Independent siblings can be reviewed without a link; they are not then claimed as a connected circuit. No later model, receipt, unrelated trajectory or equal endpoint may substitute for an actual handoff.

A paid review can succeed while its declared parent outcome is blocked. All required child operations must have succeeded, and nested children must themselves be complete. Cancelled work, failed material attempts and declined commitments remain visible. A blocked parent cannot release an operative constraint.

Each parent retains its direct child references and a bounded union of exact cited operation revisions. Repeated descendants in a diamond are counted once. The parent's own paid review is a separate operation: it does not debit its children again. `cited_spending` covers the explicitly cited descendants, not all supporting setup, reads, votes or exchanges in the engine. Total modeled work is measured separately from wallets and raw transactions.

Parent output dependencies include the child records and inherited conceptual/authority revisions. A relevant stance withdrawal, membership change or source revision invalidates affected completion and subsequent use. Completed material observations remain historical evidence; parent review does not require undoing a child's material changes.

Depth is bounded to four; direct children and request inputs to eight; distinct cited operations to 64; social exchange to two members; demand to 1–1000. The ancestor union grows with cited work and is charged. This implementation claims neither arbitrary-depth nesting nor constant storage at increasing depth.

## Access, authority and reuse

Only actual public C4 offer/shared messages can be disclosed, to their declared audience. Private intermediates and outputs cannot be imported as authored drafts. Binding ownership, cue, context and referent are checked. Cross-context use requires the explicit transfer recipe and local evidence. Common current dependencies invalidate cached/generated results after relevant revisions.

A parent is not a model; Apply refuses that schema. Release accepts only an exact owned model child. A composed system with unsupported coupling is usable for assessment or a contained trial, not expenditure performance. The existing one-attempt authorization accounting also applies to C4 shared outputs and their public aliases. A C4 Commune expenditure attempt also consumes its exact offer/reply exchange at start; cancellation, failure and restoration cannot turn that exchange into another commitment.

No recipe calls native `acquire`. A retained representation, collective summary, lesson or renewed relationship does not create practiced procedural competence. The material law, resources and actor-specific wallets remain independently authoritative.

## Audit and compatibility

`crux_composition_audit.py` reconstructs schemas, parent outcomes, links, distinct spending, context transfer, paid thresholds, retained bindings and public audiences from raw transactions and the access archive. It imports no C4 executor, transformer or selector. It then invokes the inherited auditor with the independently validated C4 outputs, so C3 consumers must retain transitive authority and actual paid access.

Only two inherited native runtime files receive hooks: `crux_execution.py` recognizes C4 paid progression; `crossing_audit.py` accepts independently validated generated content and an optional extent extension. Default C1–C3 behavior is unchanged. Exact original C3 executor layers are retained under `reference/` for the unchanged-contract timing comparison.

The full native regression population, raw mutation controls, checkpoint interruptions, reference measurements, source identities and failed development attempts accompany this release. Historical legacy-suite results remain inherited evidence, not newly rerun claims.

## Remaining boundaries

C4 demonstrates composition within a finite consumable-workshop language. It is not unrestricted natural language, an independently generated institution, universal nested coherence, psychological validation or autonomous route selection. Existing U9/U11/U12 mechanisms retain their separately documented scope. Route-wide Shell development, situated selection and distinct-setting transfer, and sustained full-release assessment remain C5, C6 and C7.
