## Implementation

Four C2 modules add immutable recipe/request definitions, finite content transformations, runtime integration and independent reconstruction. The C1 paid advance mechanism is shared through small recipe and namespace hooks. Contemplate uses a paid N return path, Act a T return path, Commune an F return path, and Integrate an N return path from ITS. Zero displacement never supplies free semantic work or automatic success. The processing policy and content algorithms are engineering constructions, not derivations attributed to the theoretical papers.

Commune consumes native offers and replies within an actually formed U11 group. The offer, reply, final shared result and later receiver use have separate paid work and access. Original positions and explicit assent are preserved. Public disclosure is limited to the addressed participants. Group or underlying stance revision invalidates dependent work; the same one-attempt allowance cannot be exercised twice. Starting an authorized action consumes that attempt even if it later fails or is cancelled; renewed participation needs renewed exchange.

Integrate retains conflicts, cycles and external prerequisites. Its prediction is a set of states reachable along a modeled trajectory, not a claim that contradictory material conditions hold simultaneously. Coupled dispatch uses the actor's received condition and the existing physical law. A model does not grant another actor's authority, ownership or practiced competence.

The legacy request `CognitiveRequest(purpose="integrate")` still means **Embody**, IT → I. Formal Integrate has its own C2 contracts. Supporting recipe labels Offer, Reply and Consume have an explicit compatibility map in the architecture note; they do not add formal Crux routes or close the C3 gates.

## Cost and efficiency

The paired unchanged-C1 comparison uses the original C1 executor retained at `reference/c1_crux_execution.py`. Five fresh workers per implementation run the same circuit. Median active time was **107.4 ms** for that reference and **104.8 ms** through C2: a ratio of **0.976**, within the prospectively declared **1.5×** tolerance. Outcomes and modeled work match. This is a regression comparison, not a speedup claim.

The new workload is a fixed panel of eight independent cases, including separately paid exchange and consumers. Each history row has three timing workers and one separately traced worker. Engine setup is excluded from active timing; fixture-authored input retention, actual exchange and downstream consumers are included. Restoration and audit are separate. Each sample starts in a fresh Python worker; restore reconstructs fresh engine instances within that worker, not a cold operating-system process.

## Limits and next milestone

C2 establishes its eight bounded contract cases. The **32-cell full-release ledger remains open**: C3–C7 still require complete crossing contracts, richer composition and nesting, route-wide Shell development, automatic situated selection, distinct semantic settings and sustained mixed runs. Input accounts and system interfaces, exchange opportunities and route requests are supplied by fixtures. This is not spontaneous route selection, unrestricted meaning or psychological validation.

The new language uses at most sixteen input references/interfaces and two participants per exchange. Material examples use the finite workshop law. Integration dispatches one primitive per paid consumer from received condition evidence; it is not a general scheduler. A second tool identity does not establish a second semantic domain.

**Next: C3 — complete both faces of the twelve crossing routes, consuming real outputs under access and authority controls.** The source README supplies reproduction commands; `tools/verify_c2.py` reconstructs the delivered decision from the recorded test populations, raw witnesses, measurement samples and file identities.
