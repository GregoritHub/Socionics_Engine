# U14 development record

Development runs use separate seeds and do not contribute to the release denominator. Entries 1–5 below precede the first release freeze; subsequent exporter, resource-control and execution diagnostics are documented separately.

1. The first population harness failed when recording work because it had not disclosed and processed current material details. The second failed maintenance because it had not processed its practice records. Both logs and source snapshots remain. The harness now uses paid observations at both boundaries; the runtime is unchanged.
2. The eight-opportunity scarcity smoke completed all opportunities, so its requested scarcity gate failed. It did not run long enough to exhaust the allocation. A separately specified 24-opportunity scarcity case demonstrates exhaustion and retained failed work. No release threshold was weakened.
3. A development protocol was assembled with case arrays at the wrong nesting level. Its empty panels initially returned success; those outputs are explicitly invalid and contribute no evidence. The runner now rejects empty panels and duplicate IDs before execution.
4. A funded-energy development case reached two uses and then exhausted its two care units before its third requested use. Accounting and continuation passed; the useful-work criterion failed. The final prospective positive allocation contains four care units at initialization; energy/material-limited cases retain their separate censoring outcomes. The original failed trajectory is preserved. No replenishment was added.
5. Complex receiver composition, alternate receiver nesting, five-person paid consent, three partial population continuations and per-owner ledger/inspector controls passed their development checks before freezing the release.

The release protocol and execution manifest are frozen only after these harness changes. Any later failed release result must remain visible and cannot be relabeled as an unused holdout.

## Exporter-only release amendment 1.1

A full HTML export of a development checkpoint exposed an ObjectId left in the wallet dictionary. The release attempt was interrupted; its completed cases, partial files, initial source manifest and source-change rejections during shutdown are retained under `interrupted_exporter_v1`. The exporter now recursively converts identities, dataclass records and enums, including the wallet and processed particulars, with a new full-export JSON/HTML regression. A first partial fix exposed an additional Particular serialization error; that failed test and candidate are also retained. The completed exporter passes all nine U14 tests and exports the full sustained development checkpoint. The behavioral runtime, panel cases, thresholds and allocation rules are unchanged. No behavioral outcome was used to tune them. All final panels are reexecuted on amendment 1.1.

## Preserved release-control failure and prospective reassessment

Care-only scarcity did not necessarily exhaust all lawful maintenance paths. Release groups generated paid repair fallback, so the original required-failure gate failed even though accounting, continuation and useful work remained valid. `population/` and the original assessment preserve those results. A separate development control (seed 3105, five people, changed timing and wear threshold) then confirmed that limiting both maintenance stocks retains actual incomplete opportunities: 18 of 24 later opportunities succeeded, with all other invariants intact. Only after that check, `supplement/protocol_v2.json` and its source manifest froze ten additional previously unexecuted combinations. No participant policy, runtime price, original panel or threshold was changed. The final report distinguishes this new assessment from the failed original expectation.

## Legacy execution failures retained

The first complete-suite attempt stopped progressing at the R14.5 name/time invariance test and was interrupted; the same test then passed in isolation. A second complete-suite run with periodic faulthandler snapshots progressed beyond that point, but the interpreter terminated with a segmentation fault after 716 completed tests. The partial trace does not establish a causal runtime defect or an environmental explanation. The root cause remains unresolved.

Both incomplete attempts remain under `legacy_stalled_attempt/` and `legacy_crashed_attempt/`. A separately frozen regression execution amendment runs the same 840 tests, without edits, in 37 fresh module processes. No test is dropped and there are no automatic retries. Its complete result is reported with that execution scope, never as a passing monolithic run.
