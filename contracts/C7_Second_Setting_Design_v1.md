# C7 remaining semantic-setting work — implementation proposal

Status: proposed and unimplemented. This document grants no release credit.
Existing route identities and polarity definitions remain unchanged. New recipes
must have their own versions and independent declarative validators. A generic
scalar cap carrying a new label is not a second domain.

## Typed extension

Introduce scoped procedure obligations as typed content: observed conditions,
per-step preconditions and effects, dependencies, responsible actors, offered and
accepted roles, unresolved alternatives, and exact evidence references. Keep the
procedure representation separate from acquired practice, physical execution and
public authority. Construct variants from the finite material law and actually
observed events; do not inject a finished answer as inferred content.

Use maintenance/procedure organization as the second domain for the existing
scalar crossing routes and reciprocal shared-resource route. For the self-routes
already operating on conditions/procedure interfaces, add distinct resource and
commitment cases with different causal responsibilities.

| Route | Candidate second-setting responsibility |
| --- | --- |
| Contemplate | Differentiate conflicting resource intentions; rehearse a contingent allocation policy while preserving hypothetical commitments. |
| Express | Give a maintenance intention preparatory physical form; execute the intended maintenance with actual acquired capacity and resources. |
| Share | Exchange a personal maintenance experience with receiver-owned reconstruction and qualification of its meaning. |
| Theorize | Construct a conditional maintenance hypothesis from accessible experiences; submit an explicit testable procedure model. |
| Embody | Relate an actual maintenance outcome to owned interpretation; retain a response that changes a later held-out maintenance decision. |
| Act | Prepare an actual resource arrangement; perform a lawful resource transfer/use with custody and exact material consequences. |
| Coordinate | Exchange observed tool conditions and dependency constraints; mutually revise who can participate in maintenance. |
| Organize | Derive an evidence-scoped maintenance dependency structure; put a qualified arrangement into operation under actual authority. |
| Identify | Interpret an offered maintenance role; accept, qualify or decline it in an owned subsequent choice. |
| Mobilize | Establish real participant readiness; perform the accepted maintenance sequence with individual payment and capability. |
| Commune | Clarify divergent procedure interpretations; renew or qualify an actual shared procedure commitment through reciprocal replies. |
| Institutionalize | Formulate conditional maintenance responsibilities from observed shared practice; ratify and apply them through exact participant votes. |
| Understand | Relate an accessible procedure to owned conditions and missing abilities; retain a supported personal response without importing competence. |
| Apply | Conduct a paid local procedure trial; execute a qualified procedure under live material and authority constraints. |
| Educate | Learner reconstructs and questions procedure dependencies; meaning repair changes the learner's prediction on a held-out precondition. Practice remains separate. |
| Integrate | Reconcile resource and commitment constraints; couple compatible arrangements without erasing dissent or double-spending resource permissions. |

## Required evidence before these count

For each face of each route: validated inputs, committed intermediate handoffs,
independent postconditions, actual downstream consumer, and matched defining-step
control. Show why the content responsibility differs materially from its C6
setting. Use generated outputs in connected families. Exercise authority changes,
refusal, missing practice, withheld observations, stale dependencies, interruption
and limited resources. Renew demand after correction and preserve Shell residue.

Only after those cells are evidenced should the final sustained panel combine
settings. The scheduler should expose pending, unchanged and stopped demands;
repetition of an old interpretation must remain distinguishable from new useful
capacity. Freeze the executed sources before the final joint release evaluation.
