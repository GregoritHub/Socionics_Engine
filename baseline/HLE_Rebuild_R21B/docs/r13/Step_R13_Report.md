# HLE R13 — integrated content and developmental memory

17 September 2026 · Release 1.3.0

**R13 complete. R12–R21 extension: 2/10 milestones complete; eight remain. Next: R14 — generated demands and participant-selected work.**

R13 moves useful finite content crossing and consequence-sensitive personal meaning into the main runtime. Its commands now share world events, Fool’s Memory, Model A processing, resources, material records, language, organization and replay. The original experimental adapter is preserved for comparison; the current `DevelopmentalWorld` no longer has its checkpoint limitation.

## Implemented changes

**Content uses the main paid processing path.** Version-one content and meaning commands hold their route, input references, declared dependencies, paid progress and processing reservation in the same journal. A partially funded job emits no usable output. Participant status hides the private unfinished candidate. Exact retries do not recharge; explicit continuation spends only unfinished work. Cancellation or invalidated input retains earlier debits without publishing the result.

**Retention is no longer a direct-address shortcut.** The learner must infer a rule, retain it through paid Write, publish a contextual binding and later pay for RecallQuery. Raw receipts and directly supplied memory addresses cannot substitute for executable access. A new paid contextual binding can retrieve the same generic rule in a changed context. Ordinary facts do not gain context-independent applicability. Currentness checks reject superseded/withdrawn/disputed capacity, stale binding and invalidated declared dependency chains while preserving historical evidence.

**Meaning is learned from actual consequences.** The recovered learner compares the last three owned action-consequence samples under paid processing; its tentative expectation becomes available only after separately paid Write and Bind. The same cue can carry different expectations for two continuing holons, and reversal in experience can reverse the expectation. Successful transfer is not mislabeled as prior unavailability because the recipient owns the object afterward. Reusing one old receipt as multiple encounters is rejected.

**Eight content roles are executable.** Alternatives, conditions, specific consent, feasible means, temporal dependency/prediction, commitment allocation, logical distinctions and shared acknowledgment have bounded typed operations. Consent and acknowledgment require actual received sender responses. The roles preserve fixed TIM/Model A structure and payload aspect despite sender activity changes. They are not general prose classification or a full individuation circuit.

**Checkpoint continuation covers unfinished work.** The allowlisted codec serializes the continuing journal, including content jobs, pending reception, memory work, personal meaning revisions, existing material and organizational operations. Replay reconstructs indexes and compares every transaction exactly. Rehashed candidate, payment, state, dependency and receipt tampering is rejected.

### Personally learned meaning changes actions

Two actors in the same continuing world use **the same Arcana 21 cue**. Three actual unavailable-transfer experiences produce a checking expectation for one actor; three actual successful-transfer experiences produce a direct-action expectation for the other. A fresh controller after checkpoint restore performs new paid contextual retrieval and independently chooses the same subsequent actions as uninterrupted execution: **inspect** versus **transfer**. Both actions complete, and the complete resulting journals agree.

In a reversal history, the retained checking expectation follows:

`true → true → true → true → false → false`

These are six successive memory revisions under the declared last-three-sample rule. The old first revision remains available as historical material; the current binding exposes revision six. Missing publication leaves the earlier expectation in force despite new experiences. Different card labels do not impose different expectations. These results establish the implemented contextual recurrence, not a uniquely proven Id/Identity interpretation or a mandatory 9/3 traversal.

### Exact interruption and cost accounting

Every prefix of an **88-event trace** restores and runs the remaining commands to the identical final checkpoint. The cutpoints include **20 partial memory transactions, 6 partial content transactions, 7 partial reception transactions and 25 partial meaning transactions**, as well as completed and failed lower-level work. In particular, the second learned-meaning revision and its partly completed Write/Bind operations are included; this is not only an endpoint checkpoint test.

Separate energy/time boundary cases, exhausted resources followed by explicit credit, duplicate retry, cancellation and stale continuation retain exact accounting. No evaluator-known falsehood receives a penalty merely because it is false.

## Verification history and source preservation

The initial continuation/audit fixtures exposed source-interface mistakes: the audit used `resource` instead of `ResourceAmount.unit`, an organization setup omitted required participant provenance, and its endpoint assertion used “left” instead of the existing status “withdrawn.” A material fixture also needed the full runtime’s actor-policy argument. These were corrected without altering runtime ledger rules or acceptance thresholds.

A substantive currentness test caught an over-restrictive new guard: it initially treated tentative ownership belief as absence of an acquired R4 checking procedure. That was repaired. Current tentative experience can retain a genuine procedural guard; withdrawal, dispute, supersession or changed contextual access still blocks execution. The failed run and its repaired test remain in the evidence.

The first full validation also encountered R12’s old assertion that all 42 baseline runtime modules must remain identical to the current engine. R13 deliberately changes codec registration and release entrypoints, so that assertion is no longer the current stage’s source-preservation claim. Its original file is retained at `reference/r12_tests/test_specification.py`. The adapted check verifies all 42 historical modules against the pinned R12 manifest and enforces the explicit three-file change set. **No frozen behavioral gate, demand threshold, seed set or R12 declaration was changed.**

Of R12’s 45 runtime modules, **42 remain byte-identical**, three are changed, and six new modules are added. The supplied R12 archive, original manifests, source documents, adapter and recovered probes remain pinned. `Source_Changes_R13.json` and `Test_Evolution_R13.json` disclose the complete change and repair history.

## Completion gate and limits

The five R13 acceptance gates have executable evidence: content identity; paid contextual current-capacity access; exact partial-work continuation/accounting; personally learned revision with consequential differences; and eight bounded content roles. The separate gate overlay records those results while leaving R14–R21 unassessed.

The scenarios still supply the tasks, training opportunities and histories. R13 does not yet make persistent consequences generate discovered demands or have participants autonomously choose the next developmental problem; that is **R14**. Generated compensation, the joint five-sign detector, conversion, full individuation, clearance and recursive/shared closure remain later gates.

The original R10/R11 large population studies and the full earlier 450-/392-/92-trajectory memory panels were **not newly rerun**. Their bundled results retain historical status; the fidelity tests listed above were rerun. The frozen **480-case R21 evaluation grid remains unexecuted**. Offline checkpoint replay is tested for correctness, not certified against R21’s sustained performance budget. Unrestricted complexity and human empirical validity remain outside this finite release claim.
