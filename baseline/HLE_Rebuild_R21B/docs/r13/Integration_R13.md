# R13: integrated content and developmental memory

## Runtime boundary

`hle.developmental.DevelopmentalWorld` extends the complete `OrganizationWorld` chain. World actions, Fool’s Memory, Model A processing, R5 material/assessment, Socion reception, composition, language and organization share one command journal with the new content and meaning operations. This is not a second simulation or the old experimental adapter with a checkpoint stub.

`hle.content_records` declares version-one commands, processing jobs, transactions and the complete R13 checkpoint. The existing allowlisted JSON codec recognizes these exact record classes. The original three R12 contract/structure/protocol modules and frozen R12 declarations are unchanged. `Source_Changes_R13.json` pins the supplied R12 archive and identifies the three inherited module changes: package version, default demonstration, and codec registration. Six runtime modules are added; older operators and demos remain available under their original names.

The original `baseline/crossing` package is preserved as a comparison source. Its old checkpoint exception remains there intentionally. The **main R13 runtime** implements checkpoint/restore; participant code must import `hle.developmental`, not the pinned experimental adapter.

## Paid content and temporary inference

`ContentCommand` names an actor, stable task identity, finite operator, exact owned input references, optional paid contextual recall result and a work quantum limit. Completed output is an owned observation. The private unfinished candidate remains inside the replay-checked processing job; participant status redacts it until completion. A deferred or partly funded operation emits no usable content output. Model A routing, eligible support position, current activity and existing price policy determine the route charge; finite content extent determines content work. Required and paid units are separate.

A new command identity can continue the same unchanged job. An exact retry of an old command returns the original event without a second debit. Changed inputs, operator or actor cannot masquerade as continuation. Explicit cancellation retains prior charges, clears the processing reservation and produces no result. A dependency invalidated during processing produces an auditable failed outcome without charging the remaining work or publishing the candidate.

Content and meaning reserve the same personal processing state used by language, organization, reception and metabolism. Relational memory can still change while processing is pending, but resumed work revalidates its dependencies. There is no separate uncharged content cursor.

## Episode, receipt and retained capacity are different

The eight legacy selection operators are integrated from the pinned adapter. Inference still distinguishes the finite candidate programs from received demonstrations. An inference receipt is historical evidence, not an executable retained rule. `hold` preserves payload identity but cannot transform an arbitrary receipt into a valid acquisition origin.

Retention requires a matching completed inference by the same actor, paid R3 Write, and an endorsed current memory revision. The learner then acquires a contextual binding through paid Bind. Later `search` and `relate` require a completed **paid RecallQuery** as `access`: supplying a receipt or a direct retained memory address is rejected. Historical raw receipt inspection cannot bypass that execution requirement.

The generic finite search/boundary rule has task-independent content. A new paid binding may apply it in another context, without copying it or inventing a new learned rule. Ordinary ownership facts keep the existing context and time filters. This extension is explicit and applies only to the declared finite rule kinds; it does not make all remembered facts universally applicable.

Executable access verifies the memory head, attitude, binding head/scope and explicitly declared current memory dependencies. Those dependencies recurse through other acquired capacities, using a visited set. Historical source/provenance links are not automatically all treated as current dependencies: an old experience remains evidence even after a newer experience is learned. Superseded, disputed or withdrawn executable memories cannot be used as current. Historical revisions remain readable.

`retained_capacity()` resolves the R12 RetainedCapacity contract from the actual memory, contextual binding, acquisition debits, practice events and dependency revisions. It is a view of these records, not an independently assignable capacity or developmental rank.

The R4 inspect-before-transfer capability is also protected from stale or withdrawn owners. A tentative ownership belief can still carry a genuinely acquired checking procedure; claim confidence and retained procedural availability are distinct. Withdrawal of the owner or a changed binding prevents guarded application without deleting the old account.

## Personal recurrence and meaning revision

The recovered holon-meaning learner is integrated under `MeaningCommand`. Its bounded sample rule is retained: compare the last three actual owned action consequences, count whether the originally offered transfer was unavailable, and keep a cautious checking expectation on a tie. A successful transfer is not mislearned as prior unavailability simply because the recipient now owns the object.

The command requires the exact completed R4 application, first enactment, matching observation, embodied memory, and paid contextual access to the preceding meaning. It rejects mismatched or foreign evidence and reuse of one experience as repeated encounters in the same scene. Comparing these samples is now charged processing work. The completed proposal must then be written and bound through separate paid memory operations before it changes contextual availability. Meaning publication must match the paid proposal exactly.

Repeated encounter → paid retrieval → consequence-sensitive proposal → paid revision → paid publication is the implemented recurrence. The same cue can acquire different expectations in different actors or contexts; later history can reverse the expectation. The controlling example uses the expectation to select an actual inspection versus direct transfer. Neither card name nor a logged recurrence label supplies the answer.

The recovered least-used cue-allocation helper remains available, with its declared tie-breaking policy. R13 does not claim spontaneous selection of goals, cues or developmental timing. The historical 9/3 traversal is retained with the prior probes; it is not imposed as a universal main-runtime schedule or presented as a uniquely validated interpretation of Id/Identity. Persistent actor/material identity, cue identity, personal expectation and IDEA κ remain distinct.

## Eight executable content roles

| Aspect | Bounded executable interpretation | Failure/control boundary |
| --- | --- | --- |
| Ne | Enumerate the offered, permitted alternatives. | No insertion of unoffered alternatives. |
| Si | Check supplied condition value, epoch, bounds and task budget. | Out-of-bounds, stale declared epoch or insufficient declared budget is invalid. |
| Fi | Filter options by a specifically received partner’s consent. | Forged sender, missing consent or superseded received response cannot authorize. |
| Te | Select authorized, ready means within the task budget. | Unmet prerequisite, missing authorization or over-budget choice cannot pass. |
| Ni | Order dependencies and compute earliest expected times, revising them after supplied availability delays. | Cycles do not produce a successful order. |
| Se | Allocate authorized commitments under a bounded resource envelope. | No overcommitment or use of unavailable commitments. |
| Ti | Differentiate explicit assertions and expose inconsistent assignments. | Contradictory assertions do not count as consistency. |
| Fe | Establish acknowledgment through actual received responses from all required participants. | A personal claim or one missing/forged response cannot establish shared acknowledgment. |

The bodies are finite typed records with explicit domains; these are executable semantic hypotheses, not a solution to content classification for arbitrary prose. In particular, task budgets/epochs are supplied content conditions, distinct from the separately charged engine wallets and clock. The interpreter can reason from fallible supplied statements; R13 does not turn them into evaluator Truth. Fi/Fe additionally authenticate the actual sender and completed reception, with supersession when a new response is received.

Aspect travels with the copied payload independently of sender activity and TIM. All sixteen fixed stacks and dimensions are preserved. Exercising complementary positions and all eight roles does not establish a four-perspective individuation circuit or a participant-generated institution.

## Continuation, resource accounting and evidence

Checkpoint serializes the complete typed journal, world configuration, actor profiles and processing/organization/semantic policies. Replay reconstructs exact queues, partially paid work, contextual memory, material revisions, capacity dependencies, current acknowledgments and processing reservations. Every replayed transaction must equal the saved transaction. Rehashing a tampered candidate, paid counter, receipt or processing state does not bypass this check.

The continuation witness checks **every prefix of an 88-event trace**, including partial content, reception, memory access/write/bind, learned-meaning processing and revision. Each restored prefix executes the same remaining commands and must produce the same complete final checkpoint. The test suite also covers credits after resource exhaustion, cancellation, dependency invalidation, the existing material chain, and the full existing organization lifecycle with appended R13 work.

An independent wallet fold uses genesis balances, explicit credits and actual work debits. It checks each before/after balance, resource conservation, final wallets and content-job paid counters. A false belief receives no evaluator-imposed energy penalty. Finite content prices remain implementation choices; measured host CPU time and a psychological energy law are not inferred from these quanta.

Offline replay necessarily traverses saved history. Normal R13 operations resolve their own indexed origins/dependencies instead of scanning every past event. This is an implementation description, not a passed R21 scaling threshold: performance under increasing inactive history, sustained population behavior and future clearance remain unassessed.
