# R5 assessment and retained correction

Version 1 · 16 September 2026 · Rules S01–S09

`AssessedWorld` extends R4 `MetabolicWorld`. Every physical action, memory operation,
Crux movement, material treatment, declaration, trial and report uses the same
append-only journal. The original mathematical, world, relational-memory and
processing implementations remain unchanged. The codec adds R5 immutable records.

## Source authority

The corrected IDEA Canon supplies the distinction between identity and correctness,
declared transformation/return tests, cumulative phases, exact equivalence and the
conditional composition theorem (especially §§3–6 and Equation 17). It does not
supply the numerical work prices or generate candidate behavior.

Unified Shell Geometry §§4–7 supplies the demand clause, path/endpoint distinction,
rest/foreclosure distinction and maintenance concept. Its mapping of individual
Shell signs to OIG signatures remains open. The foundation §§5–8 supplies the
acceptance panel and evidence boundaries. The Shadow Complex document remains a
reference for the material/carrier distinction, not a substitute for Crux v6.

The selected feature map, two-opportunity recurrence threshold, ownership grammar,
conservative affordability quote, carrier grammar and detector rules are explicit
implementation choices. Tests establish their behavior. They do not validate a
clinical theory, discover an empirical metabolic price or prove these definitions
unique. `rules.json` preserves these grades and source locations.

## Declare before engagement

A `Study` binds an immutable, versioned `AssessmentSpec` to one actor, a named
memory and object. It declares an executable operation sequence, features, path
budget, optional no-discrepancy condition, recurrence threshold, provenance and
perspective-specific contrasts. The state-space, identity and comparison IDs must
name the implemented R5 grammar. Unknown definitions reject. Changing a declaration
requires a new assessment reference; earlier records and failures remain.

Each study currently covers one protocol. Several studies can cover different
protocols; the engine does not combine them into an unproved universal guarantee.
The operation sequence is authoritative: `transform` identifies its initial
operation and `return_policy` its last. The example sequences are Theorize → Apply
→ Embody, Theorize → Understand, and Apply → Embody after an already-derived account.

The tracked features are exact:

| Feature | Value |
| --- | --- |
| `claim_links` | Ordered subject, relation, object and context tuples from the named memory's ownership claims about the selected object. |
| `claim_scope` | Those claims' declared time scopes. |
| `capacity_rules` | Sorted names of actual acquired procedures reachable from the named retained memory. |
| `perspective` | The actor's realized Crux perspective. |

Omitting a feature is explicit. For example, preserving ownership content can allow
its evidence time to change. Claim-based return is unassessed when the necessary
claims are absent; capacity-based return is unassessed without capacity. Exact
references keep actor substitution visible even when connectivity is unchanged.

`BeginTrial` captures the opening state and opportunity. `EndTrial` evaluates the
actual interval. An incomplete, unavailable or different sequence does not become
a passing return. A failed return is retained in the aggregate: later successful
trials can establish their own endpoint return while the broader unchanged claim
remains failed. The evaluator does not reset memories or refund work to force a pass.

## Four independent outcomes and the phase grid

Reports retain four `AssessmentResult` dimensions:

1. Factual agreement: pointwise simulator Truth at the report time, with exact
   context, referent and scope checks. Unknown claims remain unresolved. Empty
   memory has zero adjudicable claims and an unassessed result.
2. Identity return: the latest trial's declared features at its completed endpoints.
3. Path conditions: actual resource charges, declared discrepancy condition,
   contradicted reconstruction and witnessed external attribution within the trial.
4. Retained capacity: a previously retained checking procedure actually used
   successfully on the original object and a distinct held-out object.

Adjudicable, contradicted and unresolved counts are separate. No arbitrary combined
score is introduced. Coverage uses one declared target ownership relation: retained
means a corresponding claim exists; delivered means the latest direct observation
of that relation still agrees with current Truth. Testimony is not automatically
verified. A missing observation and a false retained account remain distinguishable.

The 16 IDEA cells are phase × perspective, in labeled I, WE, IT, ITS order. INITIATE
checks the declared alternatives. DEFINE checks explicitly limited R5 predicates:
owned memory for I, ownership grammar for IT, and the declared executable process
for ITS. WE has no dyadic predicate yet and remains unassessed. ENGAGE carries the
return evidence cumulatively. A failed distinction or return remains failed in
later cells. Successful finite trials do not establish ALIGN for the growing
simulation. This grid is separate from Crux's origin × destination table.

`FiniteIDEA` is a separate finite-table utility. It declares the complete state
space, features and transform/return maps; unavailable operations use `None`.
It checks Equation 17 exhaustively before extending successful generators to all
finite composites. The Canon's a → b → c counterexample passes once and fails on
repetition. Nothing transfers this finite proof to the growing HLE state space.

## Opportunity, error and candidate assessment

A trial can name a demanded next movement with its exact owned payload. The quote
uses R4 validation and route/content costs, plus a conservative three action units
for Apply's possible inspection and transfer. It checks both energy and time.
The quote is for completing the offered movement with resumed calls allowed,
at the opening of the trial; it is not a quote for an arbitrary whole future
correction programme. Unavailable movement, missing information and unaffordable
movement remain separate conditions.

Corrective evidence must be delivered to that actor, directly interpretable under
the ownership grammar and applicable to the current situation. Merely naming a
message, or delivering unverified testimony, is insufficient. The assessor can
adjudicate these facts; participants never receive that verdict.

The bounded candidate rules are deliberately conservative:

| Classification | Required evidence |
| --- | --- |
| Ignorance | Relevant retained claim absent; no persistent adequately evidenced prevention pattern. Repeated demand alone cannot make missing information a Shell. |
| Resource limitation | The offered movement is valid but a required resource is insufficient. |
| Stable error | A retained account can return unchanged while Truth contradicts it. That alone is not a Shell. |
| Foreclosure candidate | At least two consecutive named, affordable, directly interpretable opportunities with no paid initiation of the exact offered movement. |
| Compensation candidate | At least two consecutive adequate demands with direct contradictory evidence and actual paid reconstruction of the same still-false account. |
| Candidate unresolved | A previous candidate lacks the necessary subsequent correction evidence; a quiet interval cannot clear it. |
| Cleared in tested demands | A previous fixture candidate is followed by at least two completed, factually corrected, acceptable-path demanded trials and retained checking use on original and held-out objects. |

Rest controls have the same quiet trajectory and resources as the prevention
fixture but no demand. Foreclosure and compensation choices are deliberately
injected harness policies. Their outputs prove that these detectors distinguish
their supplied evidence. They are not runs demonstrating autonomous Shell emergence.
The clearance claim concerns those modeled candidates and tested demands only.

Path records include work addresses and charges, every relevant event, realized
operation sequence, discrepancy, reconstruction and external attribution witnesses.
Feature visibility V, net change N, cancellation K and recurrence pairs use the
declared feature projection. This is a limited operational footprint; the full
twelve OIG quotient levels and sign-specific detectors are not implemented.
Changing Crux perspectives can be ordinary valid movement. Cancellation alone
never establishes a Shell.

## Explicit material and carrier experiment

`MaterialCommand` supplies a small, separately declared grammar:

- `generate` creates addressable owned material from the actor's actual Theorize
  account, preserving its exact source.
- `externalize` changes its treatment to unowned and selects that account's intended
  recipient as the external carrier. This selector is an experimental policy.
- `express` sends a real directed attribution message when an external carrier and
  permitted link exist; delivery is the demonstrated consequence. A blocked channel
  retains a paid failure. A message is testimony, not a Truth assertion.
- `reown` retains a new owned revision and removes the external carrier. Renewed
  `express` then records withholding of external attribution.

Each operation costs one energy and one time quantum. Insufficient resources defer
without publishing the proposed material change. Foreign and stale references
reject. Retries are idempotent. There is no automatic drain attached to a false
belief: costs come from actual processing, reconstruction and actions.

These choices and their order are fixture-supplied. The account source, exact
revision chain, carrier, action, delivery, charges and later changed use are real
engine records. An ordinary ownership mistake has none of this chain and cannot
substitute for projection evidence. This is a mechanistic test fixture, not an
emergence claim. Partner interpretation and independently adapting response remain R6.

## Incremental work, continuation and limits

Reverse dependencies map actors and ownership objects to studies. Relevant
processing, observations, memory changes, resources, object changes and scheduled
scope boundaries invalidate reports. Actor dependencies are conservative: unrelated
changes for the same actor can invalidate a study. Unrelated actors/studies and
inactive clock history are not scanned each tick.

`AssessPending(limit=n)` evaluates at most n queued studies. Repeated invalidations
coalesce. Each closed trial incrementally updates its aggregate; a new assessment
does not rescan all earlier trials. Closing a trial reads its actor/object event
suffix; cost can grow with that active interval. Recurrence output can grow
quadratically with changed feature states. Future scope boundaries use a sorted
agenda, so inserting many deadlines is not constant time.

Evaluator CPU work is measured separately and does not charge actor wallets.
Declarations and reports advance journal order but create no participant receipt.
Absolute simulation time is therefore not claimed invariant to inserting extra
evaluator transactions. Semantic isolation tests compare permitted content and
selected behavior under the declared timing conditions.

Checkpoints retain the configuration, profiles, policy and complete journal.
Deterministic replay verifies every transaction and rebuilds pending work, reports,
trials, material revisions, dependency indexes, future scopes and partial R4 jobs.
Rehashed tampering is checked by replay, not just a checksum. R2, R3 and R4 loaders
remain; automatic migration of old live sessions is not supplied.

The benchmark holds active content fixed while varying inactive ticks and unrelated
studies. It measures active inspection plus assessment, checkpoint size, save time
and replay time separately. It does not close R10 population, active-graph, queue,
storage or sustained-efficiency acceptance. Python participant isolation remains
an API boundary for cooperative code.

## Reproduce

From the package root, Python 3.12 or later, standard library only:

```bash
python -m hle
python -I tools/verify.py --output /tmp/hle-r5-tests
python -I tools/r5_evidence.py --output /tmp/hle-r5-evidence --tests /tmp/hle-r5-tests/results.json
python -I tools/validate_release.py
```

`docs/acceptance_plan_R5.json` declares A01–A15. The evidence tool maps all 15 cases
to actual passing tests and retains traces, checkpoints, matched controls,
candidate lifecycle and descriptive profiles. The original papers, foundation,
roadmap and earlier reports remain in the source package.
