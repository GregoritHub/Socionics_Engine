# HLE new build Step R1 report

16 September 2026 · Rebuild release 0.1.0

**R1 is complete. Progress is 1/10 milestones; nine actionable milestones remain. Next: R2 — build the tiny deterministic world and Truth record.** The first integrated demonstrator remains R5.

R1 delivers an isolated, runnable mathematical core and validated interfaces. It does not yet deliver world simulation, memory retrieval, realized Crux transformations or Shell generation/clearance.

## What changed

The new core implements exact GF(2) algebra, all 16 Model A frames, positional fields, type coordinates, transported routing, the 16 structural intertype relations and element-preserving seat transfer. It also implements the static estafette permutation and its 64-element group extension, without adopting an automatic firing schedule.

Crux supplies all 16 routes and 32 formal movements. The route table, displacement and composition are explicit. Formal inversion does not undo an event, recover content, refund energy or establish an IDEA return.

Immutable contracts now distinguish world events, delivered observations, individual memory revisions, cue/card descriptors, contextual cue bindings, navigation state, processing history, resource charges and assessment evidence. Factual agreement, identity preservation, path conditions and retained capacity are separate results. Versioned references preserve historical identity.

## Audit findings

The 5.2.1 audit inventories **188 files, including 83 Python and 30 Erlang modules**. Import closures include package initializers: importing the old Crux perspective module reaches 10 Python modules; importing the exchange module reaches 21. The delivered runtime imports none of them.

The old memory implementation requires exactly three vertices, imposes a fixed replay sequence, assigns card rank from edge count and requires Super-Ego storage. Those rules are excluded. The new memory boundary permits variable relational structures, context-dependent cue reuse, several cues per memory and independent cursor competence. The 721-memory fixture establishes interface compatibility beyond an assumed 720-cell bound; it is not a memory-scaling result.

Crux v6 supplies an important correction to the old code's claim grading: route names are **conventions**, and the club-to-perspective map is a **postulate**. That map is not promoted to a theorem or elected as a runtime dependency. The source was recovered and preserved with the supplied papers. All 31 implemented rules and open items have a recorded source/status.

**Final result: 37/37 verification cases passed, with zero failures, errors or skips. The delivered source archive was extracted and verified again.** Each case is linked to its governing rule. Several cases exhaust a finite domain:

The first full run passed. A review then added a counterexample: work may consume its full declared budget and still fail. The initial contract rejected that case. The evidence retains the failure and repair; the corrected contract preserves the failed outcome, performed work and actual charges. Both the repaired full run and the packaged-source run pass.

No old test counts are counted as new passes. These results establish mathematical consistency and contract behavior under the declared inputs. They do not empirically validate Socionics, establish a psychological energy law or close runtime efficiency acceptance.
