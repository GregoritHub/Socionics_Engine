RESEARCH SERIES · STUDY 05 · 11 OCTOBER 2026

An isolated native engine for competing shell rules

Outcome: Six selectable rule combinations run through native paid actions, observations, practice, treatment, checkpointing and replay. The unchanged baseline remains exactly reproducible. The original repository and previous research evidence are unchanged.

What now works

The engine can distinguish total request size from unfamiliar-target load. It can also distinguish historical reownership from reownership requiring returns after an observed, retained recurrence. Configuration is an explicit host experiment command in checkpoint history, so old actions replay under old rules and later actions under the chosen profile.

The tested scope is two types (IEE and SLI), one generated pattern in its exact context, distinct targets, and an existing native capacity of two. These are controlled executable comparisons, not a general engine release.

Comparison

Both types give the same categorical outcomes. “Mixed” means two exact locally corrected targets plus one novel target. “Observed overload” is an independently attempted three-target task, then paid observation and retention of its failure. True means completed or accepted.

Under unfamiliar-target load, the mixed three-target request completes; under total load, its novel target waits. Three novel targets still fail in every profile. The change therefore isolates familiarity from request size rather than removing the capacity constraint.

Pattern-wide freshness rejects old returns after observed overload. Two new independent, paid, observed and retained returns restore eligibility. Scope-limited freshness accepts old within-capacity returns after an overload outside that capacity. Historical reownership also accepts them, for a different reason.

Observation is a real boundary

All profiles accept old returns after an overload that was executed but not observed and retained as practice. Freshness deliberately uses accessible owned evidence, not evaluator knowledge of the world. This also means the new rule is not an omniscient global safety or readiness guarantee.

The cutoff uses actual response order, not the later time practice is retained. Existing requirements for novel targets, changed partner, independent performance and use of the current capacity remain in force. Native inherited qualification uses at least the retained load, unlike Study 04’s narrower exact-load contract. No claim of full Study 04 implementation is made.

Formation and later support are separate evidence

Native approval-supported responses were completed under both optional and genuinely required approval. Their paid observed practices were correctly classified as nonindependent. The external evidence ledger records these episodes separately from the original formation history: broad reinforcement would count both; attribution-contingent reinforcement would count only unnecessary approval. These are candidate increments in an evidence ledger. The engine has no new reinforcement, extinction or formation-learning rule.

Verification

98 native checkpoint outcomes passed the final audit. All checkpoints were restored and exactly reserialized. Fourteen baseline comparisons matched the unchanged engine byte for byte, including paid work and journals. The matrix covers seven outcomes for each of two types in six experimental profiles plus the unchanged reference.

The native auditor checks received facts, operation charges, exact corrections, response bases, observation provenance, retained practices and treatments. Its copied load check was extended independently of the runtime selection expression. A separate standard-library auditor imports no engine or candidate policy: it decodes raw checkpoints, checks expected outcomes, fresh return chronology, scan charges, and the complete 98-case matrix. Freshness scans add declared exact work units; inherited paid-work accounting remains in place. This accounting is a model convention, not measured human effort or CPU cost.

Failures retained

The first nonbaseline attempt failed checkpoint replay because a process-wide rule changed old history. Amendment 01 replaced that approach with a replayable configuration command; the entire primary matrix was rerun. An interim external audit was invoked before the matrix finished and stopped at a missing baseline file. Amendment 02 adds explicit full-matrix counts; the final completed audit passed. Original code snapshots, logs and attempts remain in the archive.

What this establishes—and what remains

We now have native experimental support for separating familiarity-sensitive load, historical acquisition and recovery evidence. That is a concrete improvement in the research instrument. It does not select a universally correct theory.

  • Scope-limited freshness was tested against out-of-scope overload. No discriminating within-capacity attributed recurrence was produced in this batch; that positive invalidation test remains open.
  • Weighted difficulty, coupling and task scheduling remain Study 04 reference-model concepts. The native engine needs a versioned received-fact schema before those can become agent knowledge.
  • Multiple simultaneous matching patterns, duplicate targets, stale capacity revisions, adversarial configuration and delayed observation permutations are outside this batch’s validated scope.
  • The copied engine’s inherited global development assessment is not a fresh-recovery certificate. The experimental decision and external audit must be read separately from that inherited status.
  • The profile is host-controlled experimental configuration. It is not a paid actor inference or evidence about which rule an actor believes.
